# File-level interfaces

Moved from the superproject `.claude/CLAUDE.md` §4.5 (2026-10-08). Field data and generated
ground truth are write-once (CM-7 in the root file).

The Aug Studio exposes **no ROS interface of any kind** — files and CLI only; several other
handoffs are file-mediated too.

| Artifact | Producer → Consumer(s) | Contract |
|---|---|---|
| `.svlog` | `sss_processor_node` (from `~/raw`) → GCS replay window, SonarView | Framed Cerulean Ping Protocol stream; device ids port 1, starboard 2, platform 3; rolls at 500 MB. **Primary field data.** **Before reading, comparing or decoding one, load the superproject skill `svlog`** (`.claude/skills/svlog/SKILL.md`): which tool answers which question, Python recipes with the real field names, the corpus map, and the caveats that make sim-vs-real numbers wrong. |
| Recording session `data_root/sessions/<stamp>/` | GCS → analysis, dataset build | `waterfall/waterfall_raw.npz` = archival raw record; the AI feed is the seabed **pictures**. Created when Record turns ON; nothing exported without an active session. |
| Seabed images `seabed_XXXXX.png` + `metadata/` | GCS → detector training, Aug Studio | **Raw waterfall in the native slant-bin domain** (SonarView convention): one column per device range bin, verbatim values; the dark centre band is the physical water column, darkened by the display model (`core/display_model.py`, shared with waterfall and mosaic, stored in every JSON, losslessly invertible). Rows speed-corrected to square pixels (`seabed.row_geometry: square`, PROVISIONAL; each row copies exactly one ping's bins; revert with `ping`). **The AI is fed the pictures plus their JSON metadata** (decided 2026-09-01). **Since 2026-10-16** BlueBoat-Perception's default detector input (`fixed_gray`, its decision 6.4) is a fixed mapping of their **raw dB** (= `_world.npz:intensity_db`, the 32FC1 on the wire) and per-row gain, so offline the `_world.npz` is the detector's source; the PNG stays the operator picture and the `identity` baseline. Schema 5 since 2026-10-16 (additive: `stream_id`, `georef` convention 2 = `bottom_m` + the 0.285 m lever arm, per-row attitude and device ping numbers); `detections` always `[]`. |
| World folder `~/worlds/<path_name>/<world_name>/` | `world_builder` GUI / `generate_world` (sim) → Gazebo, `sss_sim_node`, MCS overlays (via `metadata.yaml`'s GPS ground truth) | One directory, **immutable** — every save (Edit-mode re-saves included) takes a fresh silent `_i` suffix. World (0,0) ≡ the source MCS path's `geo_anchor`; conversions via the shared equirectangular pair. `scene.npz` + `scene_manifest.yaml` are the ground truth for every simulation-derived metric the thesis reports. Retired mission bundles still load everywhere; their frozen `sonar.yaml`/`trajectory.yaml` are the resolver fallbacks. |
| YOLO dataset (Ultralytics layout) | beach labelling pipeline (real) → Aug Studio, detector training | The Aug Studio treats the input directory as **read-only** and writes a new output directory. |
| `sss_aug_dataset.yaml` | dataset author → Aug Studio | Reader rules: `augCLAUDE.md`. **`intensity_mapping` must be declared explicitly** — absent, the Aug Studio assumes `log` (dB waterfall export) and inverts on that basis, mis-inverting a linear dataset. **No in-project producer writes this file.** The GCS seabed PNG is the display model's `power` transfer (a per-image 2.0 / 98.0 stretch only in the legacy `mosaic.nadir_contrast: false` fallback, `blueboat_gcs/core/seabed_imager.py`), which no Aug Studio mapping expresses (BlueBoat-Perception `docs/REQUESTS.md` R-3). BlueBoat-Perception's datasets declare the mapping per image in `images/<stem>.json` sidecars instead (below). Emitting the file is the producer module's call (CM-3). No real (non-synthetic) dataset exists on this machine to audit. |
| Augmented dataset + `generation_manifest.json` + `statistics.md` | `sss-aug-generate` → detector training | Byte-reproducible for a given config + `master_seed`, independent of worker count. |
| Perception record logs `<root>/data/Perception_data/live/<stream_id>.jsonl`; offline runs `<root>/data/Perception_data/offline/<session>/` (`records.jsonl`, `detections.json`, `summary.json`) | `perception_node` (live) / `blueboat-perception-offline` → belief layer (future), offline analysis | One canonical JSON record per image (`blueboat_perception/image_record/1`, `BlueBoat-Perception/docs/topics.md` §4). Offline = live: byte-equal once `provenance` / `source` are removed (`--compare`). Names claimed exclusively (`-2` …); a session is opened read-only and no output may sit inside it (CM-7). `<root>` resolved as below. |
| Perception dataset `<root>/data/Dataset_data/<name>/` | `perception_node` in `mode:=dataset` (MCS launch dialog **Session: Dataset creation**, personalized-world Gazebo runs; folder `<YYYY_MM_DD-HH_MM_SS>-sim[-<note>]`, the note as the run log carries it) / the CLI's `--dataset NAME` → detector training, Aug Studio | `images/` = the **detector input** (`fixed_gray`) + per-image `<stem>.json` sidecars of Aug Studio `AcquisitionMeta` fields (`intensity_mapping: log`, `log_range_db` = the window width; validated against the Aug Studio's own model); `display/` = the GCS PNG; `raw/<stem>_db.npz`; `labels/<stem>.txt` = YOLO, one box per object (highlight + acoustic shadow) from the simulator's ground truth in a world run, empty for real data; `data.yaml` (train/val placeholders, the 29 World Builder classes of `core/data/yolo_classes_v1.json`, append-only); `manifest.json` (label counts); `ground_truth_bag/` = the simulator's `/side_scan_sonar/ground_truth/*`, archived by a separate `ros2 bag record` (re-labels offline with `blueboat-perception-offline --world --ground-truth-bag`). Contract: BlueBoat-Perception `docs/topics.md` §8. Write-once. |
| Sea-state presets `share/blueboat_sss_sim/config/sea_states.yaml`; timelines `~/.config/blueboat_mcs/sea_states/*.yaml` | presets: the sim; timelines: the MCS sea-state dialog → `sea_state_node` (`sea_schedule:=`, `/sim/sea_state/command`), the MCS launch dialog (reads the presets as a file, never imports — CM-3) | Formats `blueboat_sea_state_presets/1`, `blueboat_sea_schedule/1`. |
| Trajectory `<name>.yaml` (`blueboat_trajectory/1`) | MCS Pattern Designer → `path_generation` (real and simulated runs); the sim's World Builder (GPS-anchored entries only); the GCS (`core/deployed_path.py`, planned-path overlay) | Selected as `trajectory:=from_yaml:/abs/path.yaml` through the existing launch argument. **Watched**: `path_generation` serves a station-keeping pose at the origin until the file appears, which enables deferred GPS-anchored deployment. `<name>.meta.yaml` is editor-only. `.deployed/<name>.yaml` is regenerated every launch, never hand-edited, carries `deployed_from` but **no `geo_anchor` of its own** — map placement resolves the anchor through that key. **Real-robot run session** (2026-10-09): `path_generation` watches the single `.session/run.yaml`, which MCS rewrites atomically before every run start — `deploy_mission` (anchored) or `place_mission` (rigidly moved onto the boat's odom pose at START RUN; `placed_at`), both with `deployed_from`; deleted when the next run's path is not yet known. Never hand-edited. |
| Position/pinger CSV `<root>/data/Robot_data/{date}-{note}-poslog.csv` | `robot_interface` → offline analysis, `poslog_report.py` | **Raw field record.** One per launch — or, in a real-robot **run session** (`session_mode:=true`), **one per run** (`{date}` = run start, `{note}` = the run's note, layout from the run's follow mode; nothing between runs; every run's sidecar carries the same launch origin). Two layouts by `use_UWgps`; `target_*` columns only in the no-pinger layout, reading `/monitoring_data[4:6]` (world-frame). **Since 2026-10-08 two legend rows** (description, unit) precede the column names, data from row 4; older logs have none and are never rewritten. Read with `robot_log_schema.split_header` (first row holding `relative_x`) or pandas `header=2` for new logs. |
| Mission report folder `<root>/data/Robot_data/<csv stem>/` | `robot_interface`'s shutdown hook via the ROS-free `poslog_report.py` (also a CLI) — in a run session at every run stop, as a detached `poslog_report.py <csv> [--bag <dir>]` subprocess → operator, offline analysis | The poslog CSV, its `-origin.yaml` sidecar and a `<csv stem>.png` report are **moved** in at run end. Moving a field record is allowed, rewriting one is not (CM-7): an existing folder is never touched; re-running is a no-op. **Since v1.1 (2026-10-13), run sessions add two more:** `<date>-<note>-path.yaml` (a copy of the run's `from_yaml` mission, path runs only) and `<date>-<note>-bag/` — the run's **ros2bag** (mcap; every topic except `/side_scan_sonar/*`, `/sss_processor/*`, `/sss_ai/*`), recorded by a separate `ros2 bag record` into a hidden `Robot_data/.run-bag-<pid>-<k>/` and moved in by `poslog_report` once closed. Primary field record like the CSV (CM-7). A bag without `metadata.yaml` (recorder killed) is filed all the same; `ros2 bag reindex <dir>` rebuilds it. Replayed in Gazebo by `blueboat_control Replay_launch.py bag:=<run folder or bag>` (MCS: Gazebo → Source "From a ros2bag"). |
| Controller `.npy` `<root>/data/{ctrl}_data/{date}-{ctrl}_{sim}_data.npy` | `master_control` → offline analysis, `replay.py` | One per launch, or one per run in a run session (reserved at `start`, `{ctrl}` = that run's controller, `t` from the run's start). Schema `['t','x','y','psi','x_d','y_d','psi_d','u1','u2']`, target columns world-frame. The header row is appended as strings, so `np.save` coerces the whole array to strings — cast back on load. |

**`<root>`** for the last three is resolved at node start by `custom_functions.data_root`, first
match wins: node parameter `data_dir` → `$BLUEBOAT_DATA_DIR` → the sourced workspace (parent of
the first `$COLCON_PREFIX_PATH` entry) → the process working directory. Normally
`~/ros2_ws/data/`, **independent of the launch's working directory**. An unwritable root fails
the launch naming the path (no silent fallback); names are claimed with `O_EXCL`, so two runs
in the same second get `-2`, `-3`, … instead of overwriting (CM-7).
